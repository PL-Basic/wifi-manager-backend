# Wifi Manager 测试说明

## 测试层级

- 单元测试验证纯函数、领域规则和局部组件，不证明数据库或跨服务行为。
- 持久化测试验证 Flyway、Mapper/XML、唯一约束、锁和事务。
- 服务集成测试验证 Gateway、HTTP、Redis、Nacos、MQTT 等真实依赖。
- 浏览器测试验证路由、状态、交互和可访问性。
- 固件测试验证目标芯片构建、协议、串口、网络和真实设备行为。

较低层级的通过不能替代较高层级。构建成功不能证明业务流程，mock 测试不能
证明真实数据库或多服务链路，源码审计不能证明真实硬件行为。

## 后端入口

默认在仓库根目录使用 Maven Wrapper：

```powershell
.\mvnw.cmd test
```

需要缩小范围时使用模块 Reactor，例如：

```powershell
.\mvnw.cmd -pl auth-service,user-service,tenant-service -am test
```

测试必须针对受影响模块选择范围。失败后先定位原因，只有发生实质修改或环境
条件变化时才重跑。

## 外部依赖

MySQL、HTTP、MQTT 和设备写入默认关闭。启用真实依赖时必须使用专用测试账号、
隔离数据和明确环境变量，不得连接生产数据或依赖隐式本机配置。

- MySQL URL 必须指向专用测试 Schema，并在连接后复核数据库产品和 catalog。
- HTTP 客户端默认禁止自动重试和重定向，并设置有界超时与响应大小。
- MQTT 客户端默认使用 clean session、禁用自动重连；只读验证不得 publish。
- 任何外部写入必须有显式写入开关和专用测试账号标记。

## 数据与清理

- 测试数据使用唯一 Run ID，避免与其他会话或真实数据碰撞。
- 清理只能删除当前 Run ID 创建的数据，不执行 Flyway clean，不删除构建缓存。
- 密码、Token、Cookie、私钥和真实用户数据不得写入源码、fixture、日志或报告。

## 证据边界

测试报告只说明本次实际运行的命令、范围和结果。未运行的数据库、网络、浏览器
或硬件验证必须明确标记为未验证；测试通过不自动代表完整产品验证。
